Components

Anatomy of a component

@Component({
  selector: 'app-hero',
  templateUrl: './hero.component.html',
  styleUrls: ['./hero.component.scss'],
  standalone: true,        // Angular 17+ default
  imports: [CommonModule],
})
export class HeroComponent implements OnInit {
  @Input() name = '';             // receive data from parent
  @Output() selected = new EventEmitter<string>();

  ngOnInit() { /* runs after inputs are set */ }
}

Lifecycle hooks — order matters

ngOnChanges ngOnInit ngDoCheck ngAfterContentInit ngAfterContentChecked ngAfterViewInit ngAfterViewChecked ngOnDestroy
Use ngOnDestroy to unsubscribe from observables and clear timers — memory leaks come from forgetting this.

Content projection

<!-- parent -->
<app-card><p>Projected content</p></app-card>

<!-- card.component.html -->
<div class="card">
  <ng-content></ng-content>
</div>

Use ng-content select="[slot]" for multi-slot projection.

Templates and directives

Data binding syntax

<!-- interpolation -->
<p>{{ title }}</p>

<!-- property binding -->
<img [src]="imageUrl" [alt]="name">

<!-- event binding -->
<button (click)="save($event)">Save</button>

<!-- two-way (requires FormsModule) -->
<input [(ngModel)]="username">

Control flow (Angular 17+) vs. structural directives

<!-- New block syntax (preferred) -->
@if (user) { <p>{{ user.name }}</p> }
@else { <p>Guest</p> }

@for (item of items; track item.id) {
  <li>{{ item.name }}</li>
}

<!-- Classic directives (still valid) -->
<div *ngIf="show">...</div>
<li *ngFor="let x of list; trackBy: trackFn">
Always use track / trackBy in loops — Angular reuses DOM nodes instead of recreating them.

Pipes

{{ price | currency:'EUR' }}
{{ date | date:'dd/MM/yyyy' }}
{{ name | uppercase }}
{{ obj | json }}              // debug
{{ obs$ | async }}            // subscribe + auto-unsubscribe
Pure pipe — memoized, runs only when input ref changes Impure pipe — runs every change detection cycle (avoid)

Services and dependency injection

Creating and injecting a service

@Injectable({ providedIn: 'root' }) // singleton app-wide
export class AuthService {
  private user$ = new BehaviorSubject<User | null>(null);
  login(u: User) { this.user$.next(u); }
}

// In a component (modern inject() function)
export class NavComponent {
  auth = inject(AuthService);  // Angular 14+
  user$ = this.auth.user$;
}

Provider scopes

providedIn: 'root'

One singleton for the whole app. Most common choice.

Component providers

New instance per component. Useful for stateful UI services.

Module providers

Shared within a lazy-loaded module.

InjectionToken

Inject non-class values (config, env).

HttpClient

// Provide in app.config.ts
provideHttpClient(withInterceptors([authInterceptor]))

// In service
private http = inject(HttpClient);
getUsers() {
  return this.http.get<User[]>('/api/users');
}
HttpClient returns cold Observables — nothing happens until you subscribe (or use async pipe).

Routing

Route configuration

export const routes: Routes = [
  { path: '', component: HomeComponent },
  { path: 'users/:id', component: UserComponent },
  {
    path: 'admin',
    canActivate: [authGuard],
    loadChildren: () => import('./admin/routes')
      .then(m => m.adminRoutes)   // lazy loading
  },
  { path: '**', redirectTo: '' }
];

Reading params and navigating

export class UserComponent {
  route = inject(ActivatedRoute);
  router = inject(Router);

  id$ = this.route.paramMap.pipe(
    map(p => p.get('id'))
  );

  goHome() { this.router.navigate(['/']); }
}
Prefer route.paramMap (observable) over route.snapshot.params so the component reacts when params change without full re-creation.

Guards (functional style, Angular 14+)

export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthService);
  return auth.isLoggedIn() || inject(Router).createUrlTree(['/login']);
};

Forms

Reactive forms (preferred)

export class LoginComponent {
  fb = inject(FormBuilder);

  form = this.fb.group({
    email: ['', [Validators.required, Validators.email]],
    password: ['', Validators.minLength(8)],
  });

  submit() {
    if (this.form.valid) {
      console.log(this.form.value);
    }
  }
}
<!-- template -->
<form [formGroup]="form" (ngSubmit)="submit()">
  <input formControlName="email">
  <span *ngIf="form.get('email')?.invalid">Invalid email</span>
</form>

Template-driven vs. reactive

Template-driven

Uses ngModel. Simple forms, less boilerplate. Harder to test.

Reactive

Form defined in the class. Testable, composable, good for complex logic.

Use valueChanges observable to react to form input in real time (e.g. live search, dependent fields).

RxJS essentials

Subjects — multicasting

new Subject<T>()           // no initial value, no replay
new BehaviorSubject<T>(v)  // holds current value — use for state
new ReplaySubject<T>(n)    // replays last n values to new subs
new AsyncSubject<T>()      // emits only last value on complete

Must-know operators

src$.pipe(
  map(x => x * 2),           // transform each value
  filter(x => x > 5),        // pass only matching values
  switchMap(id =>            // cancel prev, switch to new
    http.get(`/api/${id}`)),
  mergeMap(x => doWork(x)),  // parallel, keep all
  concatMap(x => doWork(x)), // sequential, queue
  exhaustMap(x => login(x)), // ignore new while busy
  debounceTime(300),         // wait 300ms after last emit
  distinctUntilChanged(),    // skip duplicate values
  takeUntilDestroyed(),      // auto-unsub (Angular 16+)
  catchError(err => of([]))  // handle error, keep alive
)
Use switchMap for search/navigation, concatMap for ordered writes, mergeMap for parallel independent calls.

Avoid memory leaks

async pipe — auto-unsubscribes takeUntilDestroyed() — Angular 16+ takeUntil(destroy$) — manual store in subscription, call .unsubscribe()

State management

Signals (Angular 17+)

import { signal, computed, effect } from '@angular/core';

count = signal(0);
doubled = computed(() => this.count() * 2);

increment() { this.count.update(v => v + 1); }

effect(() => {
  console.log('count changed:', this.count()); // reactive side-effect
});
Signals are synchronous and granular — Angular knows exactly which component to re-render without running the full change detection tree.

Service + BehaviorSubject pattern

@Injectable({ providedIn: 'root' })
export class CartService {
  private _items = new BehaviorSubject<Item[]>([]);
  items$ = this._items.asObservable(); // read-only outside
  add(item: Item) {
    this._items.next([...this._items.value, item]);
  }
}

When to reach for a library

NgRx Store

Redux pattern. Best for large apps with complex shared state.

NgRx Signal Store

Signals-based, less boilerplate. Angular 17+ recommended.

Akita / Elf

Simpler alternatives to NgRx.

Service + Signal

Great for small/medium apps — no extra deps.

Performance

Change detection strategies

@Component({
  changeDetection: ChangeDetectionStrategy.OnPush
})

OnPush only re-renders when: an @Input reference changes, an event fires inside the component, or an observable used via async pipe emits. Much faster for large trees.

Pair OnPush with immutable data — always create new objects/arrays instead of mutating them.

Lazy loading and preloading

// app.config.ts
provideRouter(routes, withPreloading(PreloadAllModules))

// routes.ts — lazy route
{
  path: 'dashboard',
  loadComponent: () => import('./dashboard.component')
    .then(m => m.DashboardComponent)
}

Other key optimizations

track / trackBy in loops Pure pipes over methods in templates Deferrable views @defer Virtual scrolling (CDK) OnPush everywhere possible takeUntilDestroyed() to prevent leaks SSR with Angular Universal Standalone components (smaller bundles)
Avoid calling functions in templates (e.g. {{ compute() }}) — they run on every change detection cycle. Use computed signals or pure pipes instead.
