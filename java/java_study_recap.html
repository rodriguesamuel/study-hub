OOP fundamentals

The 4 pillars

Encapsulation

Hiding state behind private fields + public getters/setters.

Inheritance

A class extends another, reusing and extending behavior.

Polymorphism

Same method call behaves differently based on the object's real type.

Abstraction

Expose only what's needed; hide the implementation via interfaces or abstract classes.

Class vs. interface vs. abstract class

interface Drawable {
  void draw(); // implicitly public abstract
  default void log() { System.out.println("drawn"); }
}

abstract class Shape {
  abstract double area(); // must override
  void describe() { System.out.println("I am a shape"); }
}

class Circle extends Shape implements Drawable {
  double r;
  Circle(double r) { this.r = r; }
  public double area() { return Math.PI * r * r; }
  public void draw() { System.out.println("⬤"); }
}
Prefer interfaces over abstract classes. A class can implement many interfaces but only extend one class.

Key keywords

static — belongs to class, not instance final — can't be overridden / reassigned super — call parent method/constructor this — current instance instanceof — runtime type check

Data types & memory

Primitives vs. wrapper classes

int a = 5;          // primitive — stack, fast
Integer b = 5;      // wrapper — heap, nullable
Integer c = a;       // autoboxing (int → Integer)
int d = b;           // unboxing (Integer → int)
Avoid unboxing when the wrapper could be null — NullPointerException incoming.
byte / Byteshort / Short int / Integerlong / Long float / Floatdouble / Double char / Characterboolean / Boolean

Strings — immutable!

String s = "hello";
s.concat(" world");   // new object — s unchanged
s = s + " world";    // creates new String each time

StringBuilder sb = new StringBuilder();
sb.append("hello").append(" world"); // mutable, faster in loops
String result = sb.toString();
Use StringBuilder for string concatenation inside loops. StringJoiner / String.join() for joining with delimiters.

Stack vs. heap

Stack — stores primitives and references (fast, limited size, LIFO). Each thread has its own stack.

Heap — stores objects. Shared across threads. Managed by the Garbage Collector (GC).

Collections framework

Choose the right collection

// List — ordered, allows duplicates
List<String> list = new ArrayList<>();   // fast get
List<String> linked = new LinkedList<>(); // fast insert/remove

// Set — unique elements
Set<String> hs = new HashSet<>();        // O(1), no order
Set<String> ts = new TreeSet<>();        // sorted, O(log n)

// Map — key-value pairs
Map<String,Integer> map = new HashMap<>();   // O(1) lookup
Map<String,Integer> tm  = new TreeMap<>();   // sorted keys

Useful Map patterns

map.getOrDefault("key", 0);          // safe get
map.putIfAbsent("key", 1);           // won't overwrite
map.computeIfAbsent("key", k -> new ArrayList<>()).add("v");
map.merge("key", 1, Integer::sum);   // frequency count
map.forEach((k, v) -> System.out.println(k + " → " + v));
For thread-safe maps use ConcurrentHashMap, not Hashtable.

Complexity cheat sheet

ArrayList

get O(1) · add O(1)* · remove O(n)

LinkedList

get O(n) · add/remove O(1) at ends

HashMap

get/put/remove O(1) avg

TreeMap/Set

get/put/remove O(log n)

Exception handling

Hierarchy

Throwable → Error (don't catch: OutOfMemoryError) · Exception

Checked — must be declared or caught (IOException, SQLException)

Unchecked (RuntimeException) — NullPointerException, ArrayIndexOutOfBoundsException, IllegalArgumentException

Try-with-resources

// AutoCloseable is closed automatically
try (BufferedReader br = new BufferedReader(new FileReader("f.txt"))) {
  String line;
  while ((line = br.readLine()) != null) {
    System.out.println(line);
  }
} catch (IOException e) {
  e.printStackTrace();
} // br.close() called even if exception thrown

Custom exceptions

class InsufficientFundsException extends RuntimeException {
  private final double amount;
  InsufficientFundsException(double amount) {
    super("Need " + amount + " more");
    this.amount = amount;
  }
  public double getAmount() { return amount; }
}
Never catch Exception or Throwable silently — always log or rethrow.

Concurrency

Thread basics

// Option 1 — Runnable lambda
Thread t = new Thread(() -> System.out.println("hi"));
t.start();

// Option 2 — ExecutorService (preferred)
ExecutorService exec = Executors.newFixedThreadPool(4);
exec.submit(() -> doWork());
exec.shutdown();

Key concepts

synchronized — one thread at a time in a block/method.

volatile — ensures visibility across threads (not atomicity).

AtomicInteger — lock-free, thread-safe counter.

synchronized (this) { count++; }   // or
AtomicInteger ai = new AtomicInteger(0);
ai.incrementAndGet();
Use java.util.concurrent utilities (CountDownLatch, Semaphore, CompletableFuture) instead of raw thread coordination.

CompletableFuture (Java 8+)

CompletableFuture.supplyAsync(() -> fetchData())
  .thenApply(data -> process(data))
  .thenAccept(result -> save(result))
  .exceptionally(ex -> { log(ex); return null; });

Streams & lambdas

Stream pipeline

List<String> names = List.of("Ana", "Bob", "Alice", "Carlos");

List<String> result = names.stream()
  .filter(n -> n.startsWith("A"))       // intermediate
  .map(String::toUpperCase)              // intermediate
  .sorted()                              // intermediate
  .collect(Collectors.toList());         // terminal
// → ["ANA", "ALICE"]

Common collectors & operations

// Group by length
Map<Integer, List<String>> byLen = names.stream()
  .collect(Collectors.groupingBy(String::length));

// Sum / average
int total = nums.stream().mapToInt(Integer::intValue).sum();

// Optional — avoid null
Optional<String> first = names.stream().filter(...).findFirst();
first.ifPresent(System.out::println);
String val = first.orElse("default");
Streams are lazy — intermediate ops run only when a terminal op is called.

Key patterns to know

Singleton

class Singleton {
  private static volatile Singleton instance;
  private Singleton() {}
  public static Singleton getInstance() {
    if (instance == null) {
      synchronized (Singleton.class) {
        if (instance == null) instance = new Singleton();
      }
    }
    return instance;
  }
}

Builder

Person p = new Person.Builder()
  .name("Ana").age(30).email("a@b.com").build();
Great for objects with many optional fields. Use Lombok's @Builder to avoid boilerplate.
